# DIPlayer: какие данные используются

Это описание фактического поведения экспериментальной сборки, а не утверждение о прохождении юридической проверки продукта.

На ПК сохраняются созданные пользователем названия плейлистов, ссылки по ID на треки и их порядок, очередь ID, громкость и адрес сервера. Они находятся в `%LOCALAPPDATA%\DIPlayer`. Тексты поиска в локальную историю не записываются. Метаданные и обложки находятся в ограниченном кеше памяти только на время процесса. Аудио поступает сегментами в ограниченный буфер; дисковых копий нет.

В личном режиме собственные ключи приложения хранятся с Windows DPAPI для текущего пользователя. В серверном режиме клиент не получает секрет SoundCloud или OAuth-токен. Вход в аккаунт слушателя не используется.

Сервер Oracle получает поисковый запрос, публичную ссылку плейлиста либо ID трека и передаёт их официальному API SoundCloud. Сервер видит IP клиента для ограничения частоты. Он не создаёт пользовательских аккаунтов, не хранит плейлисты, историю запросов или музыку. Счётчики лимитов находятся в оперативной памяти. На диске хранятся ключи приложения, актуальный токен и служебные журналы состояния процесса. Nginx access log для маршрута каталога отключён; инфраструктурные ошибки могут попадать в стандартный журнал Nginx.

Звук и обложки клиент запрашивает непосредственно у SoundCloud CDN, поэтому SoundCloud/CDN видит IP клиента и адрес запрошенного ресурса. Трафик приложения использует HTTPS; серверный API слушает loopback за Nginx.

Для удаления локальных данных полностью выйдите через трей и удалите `%LOCALAPPDATA%\DIPlayer`. Для вопросов по этому экспериментальному проекту можно использовать Issues репозитория GeekyKrank/DIPlayer. В отчёты об ошибках не прикладывайте настройки, ключи, токены или подписанные URL.
