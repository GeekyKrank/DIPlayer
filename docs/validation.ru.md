# Проверки DIPlayer — 16 октября 2026

## Реальный доступ

С предоставленными ключами получение токена, поиск и /tracks/{id}/streams вернули HTTP 200. Проверен HLS MP3, разрешённый через авторизованный API-редирект на cf-hls-media.sndcdn.com. OAuth-заголовок не передаётся CDN. Секреты и подписанные URL в отчёты не записаны.

Поиск и следующая страница работают. Импортированы в SQLite реальные публичные плейлисты из 21 и 32 записей; для второго проверены обе страницы (25 + 7). Тестовые копии после проверки удалены. В ещё одном плейлисте API заявил 10 треков и вернул 9; неполный импорт сохраняет признак незавершённости.

## Выполненные проверки

- Реальное декодирование MP3 HLS, движение позиции и перемотка.
- Пауза/продолжение с проверкой стабильности позиции.
- 12 быстрых переключений источника/перемоток без ошибки аудиоядра.
- SQLite: 1001 запись, страницы по 25, последняя страница, изменение порядка, удаление и переименование.
- Прокрутка виртуализированного WPF-списка, последняя страница большой библиотеки.
- Узкое окно 460 px: снимки в evidence/release-smoke.
- Скрытое окно: таймер позиции выключен, звук продолжает обрабатываться.
- Сервер на localhost: поиск, resolve, прямой CDN URL, отклонение постороннего URL/курсора, HTTP 429 после исчерпания бюджета.
- Сборка без предупреждений; проверка NuGet не обнаружила известных уязвимостей на момент проверки.

## Условия измерений

Windows 11 x64 (build 26200), 12 логических процессоров. Release-сборки .NET 10.0.13. Реальные сетевые потоки и аудиоустройство Windows. Working Set и Private Bytes измеряются у процесса; память ядра/аудиодрайвера и разделяемые системные процессы не включены. CPU одного ядра = CPU time / wall time; системная доля дополнительно делится на 12. Это не измерения на слабом компьютере.

40-секундный прототип аудиоядра: около 55–58 МиБ Working Set, около 0,22% CPU всей машины (2,61% одного ядра). Дополнительный стресс-прогон на 25 секунд с 12 переключениями: около 61–68 МиБ, PCM не превышал 4 секунд. Данные последнего прогона: evidence/playback-probe.json.

90-секундный WPF-прогон: Working Set 160–173 МиБ, средний 163 МиБ; CPU 0,205% всей машины (2,462% одного ядра). Включал снимки окна до измерений, перемотку, паузу, скрытие и возврат окна; принудительный GC не применялся. Сводный app-selftest.json теперь содержит часовой отчёт.

Часовой x64-прогон на Aphex Twin Ambient Mix длительностью 2:14 завершён: 3600 замеров за 3611,0 секунды. Working Set 157,4–179,6 МиБ (среднее 166,9), Private Bytes 90,0–104,2 МиБ (среднее 92,3). CPU 0,0968% всей машины (1,162% одного ядра). Позиция двигалась весь прогон, самая длинная остановка — 2 замера во время запланированной паузы; PCM максимум 3,99998 секунды. Таймер позиции не включался в скрытом окне. Это промежуточная сборка с прямым API-путём; не следует выдавать эти цифры за часовой тест окончательного серверного EXE. Сырые данные: evidence/app-selftest.json и evidence/measurement-summary.json.

Диагностический режим дополнительно собирает один замер в секунду и пишет файл прогресса; в обычном приложении этого цикла нет. Во время длительного теста параллельно выполнялись сборка и другие короткие проверки на том же ПК, поэтому это наблюдения процесса в рабочей среде, а не изолированный лабораторный бенчмарк.

Дополнительное сравнение без создания скриншотов, по 90 секунд на архитектуру: x64 157–168 МиБ (среднее 161,2), x86 129–137 МиБ (среднее 131,8). На этом коротком прогоне x86 использовала примерно на 18% меньше Working Set. Средняя приватная память: 82,0 МиБ у x64 и 60,2 МиБ у x86. CPU всей машины: 0,206% и 0,177% соответственно; один короткий прогон не доказывает устойчивого преимущества CPU. Сырые данные и summary: evidence/no-capture и evidence/x86.

20-минутный x86-прогон на длинном миксе завершён: 1200 замеров за 1205,6 секунды, Working Set 128,2–136,3 МиБ (среднее 132,1), Private Bytes 59,8–67,0 МиБ. CPU 0,117% всей системы (1,408% одного ядра). Позиция двигалась весь тест, самая длинная остановка — 2 замера во время запланированной паузы; PCM максимум 3,99998 секунды. Это прямой API-путь, не серверный профиль.

Серверный путь финальной x86-сборки, 90,9 секунды через Oracle, без снимков, с проверкой callback трея: Working Set 231,3–249,9 МиБ (среднее 242,9), Private Bytes 56,8–65,6 МиБ (среднее 61,2). CPU 0,284% всей системы (3,403% одного ядра). Значок зарегистрирован Shell API, симулированный callback двойного щелчка восстановил окно. Физический щелчок мышью этим не проверяется. У серверного профиля значительно больший Working Set; причина этой разницы пока не установлена, поэтому низкие цифры прямого пути нельзя использовать как показатели публичной сборки. Требуется дальнейшее исследование. Сырые данные: evidence/final-smoke/summary.json.

## Не подтверждено

Дополнительная проверка упакованной x64-сборки через тот же Oracle-сервер, 35,2 секунды: Working Set 143,8–154,0 МиБ (среднее 148,3), Private Bytes 76,3–88,3 МиБ, CPU 0,333% всей машины (3,999% одного ядра). Повторный основной замер 91,0 секунды: Working Set 141,4–150,8 МиБ (среднее 146,0), Private Bytes 76,3–84,4 МиБ (среднее 80,1), CPU 0,203% всей машины (2,438% одного ядра). Поэтому для текущего серверного режима рекомендована x64. Источник: evidence/public-x64-final/summary.json. Длительные и короткие серверные профили проводились на разных промежуточных/финальных сборках и не являются контролируемым A/B-бенчмарком каждой правки.

## Не подтверждено

Физическое нажатие мультимедийных клавиш, сон/пробуждение Windows, отключение USB-аудио и фактическая смена endpoint не испытаны. Обработчики реализованы, но это не заменяет проверку на оборудовании. AAC-only не поддерживается. Региональная блокировка, платный доступ и удаление не проверены на реальных контрольных треках; явные коды покрыты только проверками классификации. Blocked без причины остаётся сообщением с неизвестной причиной.

Сервер Oracle активирован после явного разрешения пользователя на передачу ключей. Публичный HTTPS-поиск, resolve, выдача CDN URL, отклонение посторонних URL и HTTP 429 проверены на настоящей VM. Ключи: 0640 root:diplayer; token.json: 0600 diplayer:diplayer. Другие сервисы на VM остаются active. После короткого теста cgroup-память каталога составляла около 89 МиБ. Массовая нагрузка и разрешение SoundCloud на публичный сервис отдельно не подтверждены.

Локальные плейлисты в актуальной сборке сохраняют пользовательские названия, ID и порядок; API-метаданные обновляются страницами и не хранятся между сессиями. Дисковый кеш обложек отключён. Ранние длительные прогоны начались до этих правок и до последних исправлений обработчиков ошибок; актуальный EXE дополнительно проходит короткую проверку через Oracle. Поэтому часовой прогон не следует считать побитовым тестом финального EXE.

## Интерфейс 0.1.1-alpha, 16 октября 2026

По предоставленному образцу изменены навигация, главное окно и нижний плеер; добавлены предоставленные обои. Это статичное JPEG-изображение 736 px, без BlurEffect, анимаций и прозрачного системного окна. На ширине менее 820 px управление переносится в две строки. Виртуализация и страницы сохранены; ограничение ширины элемента видимой областью исправляет обрезание длительности в узком списке. Снимки главной, поиска и библиотеки: evidence/redesign-0.1.1.

Проверка через Oracle завершена за 90,8 секунды, 90 замеров: Working Set 152,4–161,7 МиБ (среднее 157,2); Private Bytes 97,1–105,4 МиБ (среднее 101,0); CPU 0,291% всей машины, 3,494% одного ядра. Условия ПК и метод вычисления — выше. Перед замерами сделаны снимки широкого и узкого окна, прокручена тестовая библиотека из 1001 записи; принудительный GC не применялся. Во время замеров выполнялась только лёгкая работа с браузером и документами, без параллельной сборки. Это короткий смешанный сценарий, а не доказательство длительной работы или контролируемое сравнение с 0.1.0. Новый часовой прогон не выполнялся.

Подтверждены реальное воспроизведение, перемотка, пауза/продолжение, выключение таймера в скрытом окне, восстановление минимизированного окна симулированным callback трея и последующее обновление позиции. Исправлен порядок Normal → Show при восстановлении; инициализация и диагностический запуск выполняются один раз, даже если WPF повторно вызывает Loaded. В первых прогонах обнаруживалось нестабильное восстановление; приведённый выше замер относится к исправленной сборке. Физический щелчок по значку трея отдельно не проверялся. Источник: evidence/redesign-0.1.1/app-selftest.json и summary.json.

## 0.2.0-alpha — 2026-10-17

Проверены: английские встроенные формы создания/изменения/удаления плейлистов; постраничные карточки библиотеки; фильтр; обложки и сохранение после повторного открытия SQLite; отмена/сброс картинки; постраничные треки; один клик и реальный MP3 HLS; заполнение очереди из плейлиста; кнопки паузы/следующего/предыдущего в мини-плеере; повторное открытие/скрытие; остановка таймера главного окна при скрытии. Обычное сворачивание отделено от кнопки мини-плеера. Проверка загрузки опубликованной сборки и значков входит в Build.ps1.

Новые контролируемые замеры RAM/CPU и новый часовой прогон для 0.2.0 не выполнялись. Предыдущие замеры выше нельзя выдавать за измерения этой версии. Реальные физические медиаклавиши, сон и отключение аудиоустройства по-прежнему требуют аппаратной проверки.

EXE-установщик 0.2.0-alpha проверен на текущей Windows 11 x64: первая и повторная тихая установка в отдельный тестовый каталог, сравнение SHA-256 всех установленных файлов с исходной сборкой, запуск установленного приложения с изолированной тестовой библиотекой, удаление. Контрольная сумма существующей пользовательской library.db до и после теста совпала. Ярлыки при тестовой установке отключались, чтобы не менять пользовательский ярлык; интерактивный мастер и установка на чистой отдельной машине не испытывались.

В проверке --check-volume девять промежуточных положений совпадают у ползунка, визуального Track и значения аудиодвижка; выход за границы ограничивается 0–100%.
