## Подтверждённые факты

В пустой рабочей папке не было исходного проекта. Репозиторий-ориентир не клонировался и не изменялся; прочитаны его файлы через GitHub.

Официальный поиск `GET https://api.soundcloud.com/tracks?q=ambient&limit=1` без Authorization вернул HTTP 401. Ответ сохранён в evidence/anonymous-api.json. Дополнительная проба resolve вернула HTTP 429: это ограничение частоты, а не доказательство отсутствия плейлиста. URL этой пробы — корень сайта, поэтому она также не проверяет импорт конкретного публичного плейлиста. Реальный публичный плейлист и аудиопоток пока не проверены.

Официальная документация требует зарегистрированного приложения. Public resources доступны через Client Credentials без входа слушателя, но получение токена требует client_id и client_secret. Сейчас все приложения рассматриваются как confidential. Значит, надёжный официальный вариант для распространяемого клиента без пользовательского входа требует доверенного компонента с секретом. Это вывод из документации, не успешный тест собственного приложения.

Источники:
- https://developers.soundcloud.com/docs/api/guide
- https://developers.soundcloud.com/docs/api/terms-of-use
- https://developers.soundcloud.com/docs/api/rate-limits

Перед распространением необходима отдельная проверка соответствия продукта условиям API, включая ограничения использования, атрибуцию и кеширование. Получение ключа само по себе не гарантирует одобрения любого варианта продукта.

## Архитектура ориентира

README описывает Tauri 2, React 19 и rodio. В desktop/src/lib/constants.ts заданы собственные api.scnative.space, stream.scnative.space, images.scnative.space и storage.scnative.space. В api-client.ts запросы идут через edgeFetch и собственную сессию x-session-id. streaming.ts строит /tracks/{urn}/stream и вызывает собственный /resolve. audio.ts передаёт управление нативной части через invoke. network/audio_route.rs выбирает сетевые маршруты и обрабатывает редиректы. Это система с собственной инфраструктурой, а не пример автономного официального API без ключей.

В audio/decode.rs имеются пути с Cursor<Vec<u8>> и bytes.to_vec(). Перенос такого пути противоречил бы требованию не хранить полный трек и копии в RAM. Эти модули не копировались.

Проверенные файлы доступны по https://github.com/zxcloli666/SoundCloud-Desktop/tree/main/desktop . Наблюдения относятся к main на момент проверки; commit SHA не зафиксирован, поэтому это не воспроизводимый аудит конкретной ревизии.

Решение об аудиодвижке принимается только после теста реального ответа API. dotnet SDK в PATH и C:\Program Files\dotnet не найден; присутствует .NET Framework v4, что не заменяет современный SDK.

## Минимальный сервер для Oracle Cloud

Предлагаемый вариант, пока не реализован и не развёрнут: один небольшой сервис на уже существующей VM, HTTPS через Caddy, без PostgreSQL, без проксирования и хранения аудио. Секрет доступен только сервису через файл с правами владельца или системное хранилище. Токен и single-use refresh token сохраняются атомарно, обновляются под единственной блокировкой; не выдаются клиентам.

Только фиксированные операции: поиск (25 строк), resolve публичной ссылки, страница треков плейлиста, разрешение потока конкретного трека. Никакого произвольного URL-прокси. Проверять origin next_href и разрешённые API paths; не следовать пользовательским адресам во внутреннюю сеть. Поток после разрешения идёт напрямую с разрешённого SoundCloud CDN на клиент. Если это невозможно для фактической выдачи, сначала пересмотреть решение, а не незаметно проксировать весь звук.

Начальные проектные пределы: 1 запрос/с на установку, burst 3, 4 одновременных запроса upstream, таймаут 10 с, ответ до 1 MiB. Закрытый доступ для личного клиента через отдельный отзываемый ключ, который не является секретом SoundCloud. Короткий ограниченный кеш метаданных только в пределах разрешённых условий API. Логи без запросов поиска, ключей и подписанных URL; ротация 10 MiB. Хранятся настройки, секрет, токены и счётчики; локальные плейлисты остаются на ПК.

Бюджет приложения: memory.max=128 MiB, CPUQuota=25%, отказ при исчерпании квоты вместо платного масштабирования. Это настройки для будущей проверки, не измерения. Тарифы и наличие Always Free ресурсов конкретного Oracle tenancy не проверены; нулевая стоимость не гарантируется. Использовать существующую подходящую VM без создания платных ресурсов; лимиты облачного биллинга требуют отдельной проверки перед развёртыванием.

## Дальнейший контрольный этап

Нужны регистрация собственного приложения и серверный доступ к его credentials, либо временный application access token для локальной проверки без распространения. Затем: успешный поиск, resolve конкретного публичного плейлиста, метаданные трека, выдача потока, реальное декодирование и перемотка. До этого создавать все экраны противоречило бы заданному порядку.

Ошибки нельзя угадывать: 401 — авторизация приложения; 429 — квота; сетевое исключение — сеть; 404 — ресурс не найден (не обязательно удалён). blocked без причины — «Недоступен; причина не сообщена». Отдельные сообщения региона, оплаты и удаления показывать только при соответствующем явном сигнале. preview не обозначать полноценным треком.

После успешного прототипа: модули UI, Catalog, Import, Queue, Playback, Storage и WindowsIntegration; отмена поиска и проверка поколения ответа; страницы по 25; виртуализация Recycling; обложки 64 px с ограниченным кешем; позиция 1 Гц только у видимого окна; ни одного UI-таймера в трее. Предел аудиобуфера измерить и проверить на длинном миксе, не просто задать в конфигурации.
